# Simple CRUD API on ECS Fargate (Terraform)

Runs the Django REST API from `Bla-vk/Simple-CRUD-API` on ECS Fargate behind an Application Load Balancer. The image is built from your own Dockerfile, and the Django secret key is generated by Terraform and injected from AWS Secrets Manager.

## Folder layout

```
ecs-django-project/
├── django-docker/      <- copy these two files into the ROOT of your Simple-CRUD-API repo
│   ├── Dockerfile
│   └── .dockerignore
└── terraform/          <- put this folder in its own repo, or inside Simple-CRUD-API as /terraform
```

## What Terraform creates

| File | Resources |
|---|---|
| `network.tf` | VPC, internet gateway, 2 public subnets in 2 AZs, route table, automatic lookup of your public IP |
| `security.tf` | Load balancer security group (port 80 from your IP only), task security group (port 8000 from the load balancer only) |
| `ecr.tf` | ECR repository (immutable tags, scan on push, keeps the last 5 images) |
| `secrets.tf` | A random 64-character Django secret key stored in Secrets Manager |
| `iam.tf` | Execution role (pulls the image, writes logs, reads the secret) and an empty task role for your own code |
| `logs.tf` | CloudWatch log group, 7-day retention |
| `alb.tf` | Load balancer, target group checking `/api/v1/locations/`, HTTP listener |
| `ecs.tf` | Cluster, Fargate task definition, service with a deployment circuit breaker |

Tasks run in public subnets with public IPs, so there is no NAT gateway to pay for. The task security group still blocks everything except the load balancer.

## Cost and cleanup

The load balancer and the Fargate task bill by the hour while they exist. Set up an AWS Budget alert first, and run `terraform destroy` as soon as you have your screenshots.

## Part 1: Dockerfile (in the Simple-CRUD-API repo)

1. Copy `Dockerfile` and `.dockerignore` from `django-docker/` into the repo root, next to `manage.py` and `requirements.txt`.
2. Build and test locally (Docker Desktop or Docker Engine must be running):
   ```bash
   docker build -t simple-crud-api .
   docker run --rm -p 8000:8000 \
     -e DJANGO_SECRET_KEY='any-long-random-value-for-testing' \
     -e DJANGO_DEBUG=0 \
     -e DJANGO_ALLOWED_HOSTS='*' \
     simple-crud-api
   ```
3. In a second terminal: `curl http://localhost:8000/api/v1/locations/`. You should get JSON with `"results": []`.
4. Commit the two files and push.

The container runs `migrate` every time it starts, then gunicorn. That is fine for a demo because SQLite lives inside the container and is recreated whenever the task is replaced.

## Part 2: Deploy it

1. Check the backend block in `providers.tf` (bucket, region, profile). Copy `terraform.tfvars.example` to `terraform.tfvars` and edit it.
2. `terraform init`
3. Create the repository first, because the service needs an image that already exists:
   ```bash
   terraform apply -target=aws_ecr_repository.app
   ```
4. Build and push the image. Run this from the **Simple-CRUD-API repo root**, and set `TF` to the path of this `terraform` folder. `--platform linux/amd64` matters if you are on an Apple Silicon Mac, because the task definition runs on X86_64:
   ```bash
   TF=/path/to/terraform
   REPO=$(terraform -chdir=$TF output -raw ecr_repository_url)
   aws ecr get-login-password --region eu-west-2 --profile vscode \
     | docker login --username AWS --password-stdin "${REPO%%/*}"
   docker build --platform linux/amd64 -t "$REPO:v1" .
   docker push "$REPO:v1"
   ```
5. Back in the `terraform` folder, create everything else:
   ```bash
   terraform plan
   terraform apply
   ```
6. Wait one to two minutes for the target to become healthy, then test:
   ```bash
   ALB=$(terraform output -raw alb_dns_name)
   curl -X POST http://$ALB/api/v1/locations/ -H 'Content-Type: application/json' -d '{"locationName":"Warehouse A"}'
   curl http://$ALB/api/v1/locations/
   ```
7. Take screenshots: the curl results, the ECS service with a running task, the target group showing healthy, the log group, and the secret in Secrets Manager (do not reveal the value).
8. Ship a new version: rebuild and push with tag `v2`, set `image_tag = "v2"` in `terraform.tfvars`, then `terraform apply`. ECS replaces the task gradually, and rolls back if the new one is unhealthy.
9. `terraform destroy` when finished.

## How the pieces connect

| Part of your app | Where it is set |
|---|---|
| Port 8000 | Dockerfile `EXPOSE` and `--bind`, `container_port` variable, the task security group, the target group |
| `DJANGO_SECRET_KEY` | Generated in `secrets.tf`, injected by ECS from Secrets Manager through the `secrets` block in `ecs.tf` |
| `DJANGO_DEBUG=0` | `environment` block in `ecs.tf` |
| `DJANGO_ALLOWED_HOSTS=*` | `environment` block in `ecs.tf`. The load balancer health check sends the task's private IP as the Host header, so a fixed list would fail it. Safe here because only your IP can reach the load balancer. |
| Health check | `health_check_path` variable, default `/api/v1/locations/` |

## If something fails

| Symptom | Likely cause and fix |
|---|---|
| Tasks keep restarting | Open the log group. Usually a Python error or a missing environment variable. |
| `ImproperlyConfigured` about the secret key | The secret was not injected. Check that the execution role policy in `iam.tf` applied. |
| Target stays unhealthy, logs show `Invalid HTTP_HOST header` | `DJANGO_ALLOWED_HOSTS` is not `*` in the task definition. |
| `CannotPullContainerError` | The tag does not exist in ECR. Check `image_tag`. |
| `exec format error` in the logs | The image was built for ARM. Rebuild with `--platform linux/amd64`. |
| 504 or timeout from curl | Your IP changed since the last apply. Run `terraform apply` again. |
| Push rejected: tag already exists | Tags are immutable. Use a new tag such as `v2`. |
| Data disappears after a new deploy | Expected with SQLite. Moving to RDS Postgres is the proper fix. |

## Known limits

- SQLite data is lost whenever the task is replaced, and `desired_count` must stay at 1.
- Traffic is HTTP only. HTTPS needs a domain and an ACM certificate.
- The secret key is stored in Terraform state, which is why the state bucket is encrypted.

## Checks

`tofu fmt` passes on these files. They have not been validated against the AWS provider, and the Docker image has not been built here, so run `terraform fmt -check`, `terraform validate` and the local `docker build` yourself.
